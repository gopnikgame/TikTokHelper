# TikTokHelper

TikTokHelper — браузерный пульт для уже запущенной трансляции TikTok LIVE. Он выводит чат на большой экран, показывает подарки и воспроизводит назначенные звуки, включая корректную обработку серий.

Приложение не запускает трансляцию, не публикует видео и не управляет TikTok-аккаунтом. Стример запускает LIVE на телефоне, а TikTokHelper подключается к нему по публичному TikTok ID.

> Ветка `rewrite/typescript` — актуальная веб-версия проекта. Исходная C#/Electron-реализация сохранена в истории и зафиксирована тегом `legacy-aspnet-final`.

## Возможности

- подключение к активному TikTok LIVE по имени пользователя;
- читаемый чат с TikTok-смайлами и состояниями подключения/reconnect;
- лента подарков с ID, названием, изображением и количеством;
- общий каталог звуков и персональные привязки подарков для каждого рабочего пространства;
- загрузка WAV, MP3, OGG и M4A до 10 МБ;
- последовательное воспроизведение серий либо регулируемое наложение в процентах от длительности звука;
- ограничение одновременных звуков, громкость и немедленная очистка очереди;
- безопасная модерация общей библиотеки: карантин администратором перед окончательным удалением;
- авторизация через отдельный VLine Auth Bridge и изоляция рабочих пространств;
- локальный доверенный доступ без повторного входа;
- настраиваемые уровни поддержки, озвучивание разрешённых сообщений и реакции на события;
- persistent-кэш только используемых звуков с SHA-256, проверкой целостности и fallback на обычный `<audio>`;
- один владелец звука между вкладками браузера, чтобы события не воспроизводились дважды.

Озвучивание сообщений, правила поддержки и диагностические функции развиваются поэтапно. Ручная проверка полного браузерного набора ещё продолжается; актуальный статус аудиокэша записан в [docs/audio-cache-verification.md](docs/audio-cache-verification.md).

## Архитектура

| Компонент | Назначение |
| --- | --- |
| `apps/server` | Fastify API, Socket.IO, TikTok-коннектор, авторизация и доступ к PostgreSQL |
| `apps/web` | React + Vite, операторский интерфейс, звук и синтез речи в браузере |
| `packages/contracts` | Общие TypeScript-типы и JSON Schema для HTTP/Socket.IO границ |
| PostgreSQL | Пользователи, рабочие пространства, настройки, каталог, привязки и минимальные idempotency-данные |
| Docker Compose | Один экземпляр приложения и один PostgreSQL без публичного порта БД |

TikTok-соединение принадлежит серверу. Перезагрузка браузера не создаёт второе upstream-соединение: клиент сначала получает снимок текущего состояния, затем принимает новые события через Socket.IO.

Звук и синтез речи выполняются в браузере, где находится устройство вывода. Поэтому после открытия страницы пользователь должен один раз нажать **«Включить звук»**.

## Требования

- Node.js 24 или новее;
- pnpm 11.19.0;
- Docker с Compose v2;
- PostgreSQL 18 для штатной Compose-конфигурации;
- HTTPS для публичного размещения и работы браузерных API.

Точные версии JavaScript-зависимостей зафиксированы в `pnpm-lock.yaml`.

```bash
pnpm install --frozen-lockfile
pnpm run dev
```

Основные проверки:

pnpm run lint

`pnpm run verify` последовательно запускает lint, типизацию, все тесты и production-сборку. Подробнее: [docs/development.md](docs/development.md).

## Запуск через Docker Compose

Runtime-секреты не должны попадать в Git или Docker image. Перед запуском создайте каталог `secrets/` и два файла:

```text
secrets/db_password
secrets/tiktok_helper_client_secret
```

Первый содержит пароль отдельного пользователя PostgreSQL. Второй содержит секрет клиента VLine Auth Bridge; при локальном запуске без Bridge файл может быть пустым, но должен существовать для Compose.

Проверка, сборка и запуск:

```bash
docker compose config --quiet
docker compose build
docker compose up -d db
docker compose --profile tools run --rm migrate
docker compose up -d app
docker compose ps
curl --fail http://127.0.0.1:3000/ready
```

По умолчанию приложение публикуется только на `127.0.0.1:3000`. Если внешний reverse proxy находится на другом узле доверенной сети, адрес привязки задаётся через `APP_BIND_ADDRESS` в локальном `.env`.

Никогда не используйте `docker compose down -v` для обычного обновления: эта команда удалит постоянные данные после удаления volumes. Перед миграцией сделайте дамп PostgreSQL и резервную копию media-volume.

Полный production-порядок описан в [deploy/README.md](deploy/README.md).

## Конфигурация

Основные переменные окружения:

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Полная строка PostgreSQL при запуске вне Compose |
| `HOST`, `PORT` | Адрес и порт Fastify; значения по умолчанию — `127.0.0.1:3000` |
| `APP_BIND_ADDRESS` | Host binding порта Compose |
| `SOUND_ROOT` | Каталог встроенных звуков; задаётся Docker image |
| `SOUND_UPLOAD_ROOT` | Постоянный каталог пользовательских загрузок |
| `TIKTOK_PROXY_URL` | Необязательный proxy для исходящего TikTok-коннектора |
| `VLINE_BRIDGE_*` | Параметры внешней авторизации VLine |

Частичная конфигурация `VLINE_BRIDGE_*` считается ошибкой и останавливает запуск. Секрет клиента передаётся только серверу. См. [docs/authentication-configuration.md](docs/authentication-configuration.md).

## Данные и приватность

- Полные сырые TikTok-события и постоянная история чата по умолчанию не сохраняются.
- В браузерный аудиокэш не попадают API-ответы, cookies, чат, участники эфира или данные авторизации.
- Пароли, токены, cookies, `.env`, дампы БД и загруженные пользователями медиа не должны коммититься.
- Доступ к Socket.IO room проверяется отдельно от факта аутентификации.
- Загруженный звук проверяется по фактической сигнатуре файла; браузерные метаданные не считаются доверенными.

## Ограничения

- `tiktok-live-connector` — неофициальный reverse-engineering проект, не связанный с TikTok или ByteDance. Изменения TikTok могут временно нарушить подключение.
- Текущая production-модель рассчитана на один экземпляр backend; Redis и распределённое владение коннектором не используются.
- Поддержка форматов зависит от браузера. Если Web Audio не декодирует файл, приложение пытается воспроизвести его через HTML media element.
- Устанавливаемая PWA-основа готова: manifest, иконки, безопасный офлайн-экран и явное обновление после остановки эфира. Установка на реальных Safari/iPhone, Android, Firefox и Yandex Browser ещё требует ручной проверки.
- Для экспериментальной локальной нейроозвучки выбран Sherpa-ONNX Web. Для администра готов ручной загрузчик с проверкой SHA-256 и отдельным кэшем, но пакеты и движок ещё не опубликованы в production. Системный `speechSynthesis` остаётся рабочим и резервным движком до измерений на реальных браузерах и устройствах.
- Ручные проверки Firefox, Safari, iPhone/iPad, Android Chromium и Yandex Browser отмечаются отдельно и не считаются пройденными автоматически.
